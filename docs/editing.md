# 編集の作り方（伸びているショート30本の実測）

Gemini に YouTube の URL を渡すと動画そのものを見られる。伸びている日本語の
解説ショート30本を1本ずつ見せて、企画や内容ではなく「編集の手つき」だけを
書き出させた。集計は `~/yt-analysis/data/craft.md`、1本ずつの記録は
`craft_raw.md`（`python3 ~/yt-analysis/study.py --craft -n 30` で作り直せる）。

感想ではなく数で出したので、どこに手を入れるかの優先順位がそのまま出た。

## 数字

| 項目 | 30本中 |
|---|---|
| 文字に**フチ** | 30 |
| 文字に**影** | 29 |
| 常に画面が動いている | 24 |
| 文字の下に**背景の板**（帯） | 23 |
| 文字が**ポンと一瞬で**出る | 26 |
| 単純なカット以外の切り替えがある | 15 |
| 切り替えの瞬間に**音**が当たっている | 15 |
| 文字が拡大しながら出る | 4 |
| BGMを途中で変える／止める | 2 |

切り替えの種類（多い順）: ズーム 11 ／ 揺れ 6 ／ フラッシュ 3 ／ スライド 3

「プロっぽさ」の理由として挙がった順:
1. 映像・文字・効果音がぴたりと合っている（10本）
2. 常に画面を動かす（24本）
3. 視線誘導＝強調箇所の背景板と色分け（23本）

## ここから直したこと

**影（29/30）** が一番大きい穴だった。フチだけだと文字が背景に貼り付いて
見える。`render.SHADOW` を足して `rich()` が本体の前に影を一周描くようにした。
テロップ・黒板・図の注記すべてに同時に効く。

**背景の板（23/30）**。`render.plate()` を足して、テロップと stage の行の下に
角丸の半透明の板を敷く。黒板の上でも実写の上でも同じ濃さで読める。

**音を文字のコマに当てる（プロっぽさ1位）**。`sound.se_events()` は、
図や `se` を明示したショットでは文字が無音で出ていた。`add` がある
ショットには必ず出現のコマに音を置くようにした（同時刻に既に音があれば足さない）。

**切り替えはズーム（11/30）が主役**。フラッシュは3本しかない。派手さで負けて
いるのではなく、当て方で負けていた。`render.PUNCH_*` を足して、全カットの頭で
寄りをわずかに行き過ぎさせて戻す。白フラッシュ（`flash=True`）は話が裏返る
3か所だけに絞った。揺れ（`apply_shake`）は決め台詞に当てる。

**出し方は「ポン」（26/30）**。以前はスライドさせていた。伸び縮みを
見せる演出ではなく4コマで収める当てにした（`render.POP_IN = 0.13`）。

## やらなかったこと

- BGMの差し替え。30本中2本しかやっていない。効果に対して手間が重い。
- 素材の切り抜き合成・3Dアニメ。各1本。Python の2D描画の延長では割に合わない。

## 記録が消えないように

`study.py` は以前、30本ぶんの分析をメモリに貯めて最後にまとめて書いていた。
途中で無料枠が尽きると全部消える。いまは1本見るたびに追記し、走らせ直すと
記録済みの動画IDを飛ばして続きから始まる。Gemini のモデルも枠切れで
順に落ちる（`study.py` の `MODELS`、`gtts.py` の `MODELS`）。
