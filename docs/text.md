# 画面の文字の置き方（伸びているショート40本の実測）

`python3 ~/yt-analysis/study.py --text -n 40` で、伸びている日本語の解説
ショート40本を1本ずつ Gemini に見せ、画面に出る文字の置き方だけを答えさせた。
集計は `~/yt-analysis/data/text.md`、1本ずつは `text_raw.md`。

## 数字

| 項目 | 40本中 |
|---|---|
| 同時に出す行数：**2行** | **23** |
| 同時に出す行数：3行以上 | 16 |
| 同時に出す行数：1行 | 1 |
| 前の文字を**消す** | **34** |
| 前の文字を残す | 6 |
| 位置：**上〜中央** | **33** |
| 位置：下部 | 7 |
| 位置を固定している | 30 |
| 行間に**余裕がある** | **33** |
| 行間が詰まっている | 7 |
| 背景の板が重なっている | **0** |
| **映像が主役** | **38** |
| 文字が主役 | 2 |

1行の文字数は 5〜10文字が圧倒的。

## ここから直したこと

**板の重なり（0/40）**。40本中1本も重なっていない。こちらは3行積み上がる所で
板どうしが32px重なっていた。原因は行送り `STAGE_LH` を148pxと手で置いて
いたこと。これは板を「フォントの公称サイズ」で作っていた頃の値で、板を
実際のインクに合わせた結果、板の高さが180pxになって行送りを追い越していた。
行送りも実測から出すようにした（インク＋影＋余白の上下＋隙間12px＝192px）。

**行数（2行が23本）**。既定を3行から2行に下げた。ただし `stack=3` と書けば
増やせるようにして、揚力の説明（翼は上向き→空気を下に押す→翼は上へ）だけ
3行のまま残した。あの3つが並んでいること自体が説明の中身なので、
2行にすると話の筋が画面から消える。

**位置（下部は7本）**。下端を 0.760 から 0.700 に上げた。下部が少数派なのに
加えて、板の下端が画面の86%まで来ていて、縦動画のUI（いいね・コメント）と
重なる位置だった。いまは80%で収まる。

## 判断が要る所

**古い行を薄くして残す方式は、40本のうち1本もやっていない。**
34本が消す、6本が残す（残す場合は薄くせずそのまま）。

この「積み上げる」設計は、もらった336万再生の参考動画を実測して作った。
ただしあれは長尺で、こちらは50秒のショート。ショートでは消すのが主流。

いまは2行（＝いま出ている行＋直前の1行）に減らしたので、実測で一番多い
「2行」の形にはなっている。ここから先、完全に消す形にするかどうかは、
説明の積み上がりを捨てるかどうかの判断なので、勝手には変えていない。

## 従わなかった指摘

「1行8〜12文字を5〜10文字に減らせ」は入れていない。8〜12文字というのは
こちらが質問文に書いた自己申告で、実際の台本を数えると
翼は上向き(5)／翼は上へ(4)／逆さまでも飛ぶ(7)／これと全く同じ(7)など、
すでに5〜10文字に収まっている。測らずに直すと逆に悪くなる。
